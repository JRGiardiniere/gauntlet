Read the brief
Brief · E-01written by the agent, from the Dossier and the code

Read the run once into plain data, then hand it to one of two renderers.

renderStrip decides which layout you get in two places at once. The surface check at the top only says whether a drawing could exist; whether one does is settled by which branch happened to call track(), which writes the outer drawing as a side effect. The ended branch never calls it, so off the terminal an ended run silently falls back to the text layout — the P3 at mod/strip.ts:290 in this same Dossier is that consequence.

What each later change had to hold in mind. Adding a run state meant remembering to call track() or the drawing vanished; changing the finished counts meant knowing cells was rebuilt and trimmed; moving a button meant following both trees. After the fix each of these is a field on StripState or a line in one renderer.
