## Findings considered and rejected

- A dependency-only upgrade is insufficient: the spike demonstrated final-API
  compile failures and partition behavior regressions, so source migration is
  required.
- Staying on Vitest 4 is not viable because `@effect/vitest@4.0.0` requires
  Vitest 5. The spike found no substantial blocker to that required upgrade.
- Leaving `@effect/tsgo` at 0.47.1 was rejected after the scope was expanded to
  the complete recommended Effect 4 stack. Version 0.48.0 supports the repo's
  existing TypeScript/Oxlint/tsgolint pins and adds recommended stability
  diagnostics plus scoped allowlists.
- Disabling unstable-API diagnostics was rejected. The plan keeps the 0.48.0
  recommended preset and allows only the deliberately adopted Effect CLI, HTTP,
  and process module families through the language-service configuration.
- Leaving TypeScript unpatched or enabling Effect diagnostics in both the
  language service and Oxlint was rejected. The aligned setup patches both,
  keeps Oxlint as the single diagnostics authority with `diagnostics: false`,
  and retains editor refactors, quick fixes, quickinfo, and completions.
- Changing shared Convoy rules was rejected because the installed TSGO preset
  already owns the new diagnostics. Only its stale README and the shared Effect
  skill need global documentation corrections; the project-specific allowlist
  belongs in Gauntlet's `tsconfig.json`.
- Preserving `Array.partition` in judgment resolution was rejected because its
  two same-typed positional outputs already caused migration risk; an explicit
  named single-pass split is smaller and harder to invert.
- Replacing Effect CLI, HTTP, or process adapters with native APIs was rejected
  because it broadens behavior and verification without simplifying the
  migration.
